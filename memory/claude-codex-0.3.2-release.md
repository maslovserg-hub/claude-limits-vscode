# Claude + Codex: состояние на 2026-07-30

## Обязательные правила работы

1. Не менять код без явного разрешения пользователя. Перед правками одной строкой объяснить, что именно будет изменено, и дождаться подтверждения, если его ещё не было.
2. Не повышать номер версии без прямого указания. **0.3.2 опубликована в Marketplace (подтверждено 2026-08-01); текущая версия для публикации — 0.3.3** (фикс блокировки node, см. [[usage-api-blocks-node]]).
3. Внутренний ID нельзя менять: `publisher = maslovserg`, `name = claude-limits`, полный Marketplace ID — `maslovserg.claude-limits`. На нём находятся имя издателя, установки и рейтинг.
4. Пользователь сам публикует расширение в Marketplace. Версия 0.3.2 на момент завершения сессии ещё не опубликована и свободна.
5. Перед упаковкой обновлять `CHANGELOG.md` и `README.md`, запускать компиляцию и полный набор тестов, затем проверять содержимое VSIX.

## Поведение расширения

- Claude и Codex имеют отдельные соседние status bar items и общий refresh.
- Автообновление выполняется каждые 5 минут (до 0.3.3 было 60 секунд — эндпоинт лимитов отвечал 429 на частые запросы).
- Claude показывает сессионное, недельное и при наличии Sonnet-окно.
- Codex получает живые данные через локальный `codex app-server`.
- На проверенном Plus-аккаунте Codex реально отдавал только `primary` с `windowDurationMins = 10080` и `secondary = null`; поэтому показывается только недельное окно, без выдуманного 300-минутного лимита.
- Для Claude и Codex есть отдельные режимы видимости `auto`, `always`, `hidden`; по умолчанию `auto`.
- При исчерпании лимита индикатор остаётся и показывает 100%; в `auto` он скрывается после выхода из соответствующего аккаунта.
- Email Codex не входит в ответ лимитов `account/rateLimits/read`. Раньше его давал `account/read`, но **с 2026-08-01 тот отвечает `{"account": null, "requiresOpenaiAuth": true}`** — регресс на стороне Codex, не наш. С 0.3.3 имя и почта читаются из `id_token` в `~/.codex/auth.json` (чистая функция `parseCodexAccountLabel` в `limits.ts`, покрыта тестами); ответ app-server остаётся приоритетным источником, если он непустой.

## Marketplace и локальная карточка

- Название, иконка и описание карточки VS Code для известного ID могут приходить из Marketplace, а не из локального VSIX.
- До публикации 0.3.2 Marketplace может показывать старое оформление вместе с существующей статистикой.
- После публикации `claude-limits-0.3.2.vsix` в существующую карточку новое оформление должно появиться без потери установок и рейтинга.
- Нельзя решать кэш карточки сменой внутреннего `name`: это создаёт новое расширение без статистики.

## Ошибочные подходы, не повторять

- Не менять ID на `maslovserg.claude-codex-limits`: это отделяет расширение от старой Marketplace-карточки.
- Не повышать версию до 0.3.3/0.3.4/0.3.5 без разрешения: пользователь специально оставил 0.3.2 для публикации.
- Не подменять новую иконку старыми файлами с прозрачностью.
- Не использовать генеративное удаление фона, если пользователь уже подготовил финальную иконку.
- Не утверждать, что Marketplace-карточка обновилась, пока новая версия фактически не опубликована.
