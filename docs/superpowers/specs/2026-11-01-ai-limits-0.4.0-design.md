Добавить мониторинг лимитов Kimi Code третьим индикатором в Status Bar, переименовать расширение под нескольких провайдеров и дать более компактные режимы отображения.

## 3. Мониторинг Kimi Code

**Источник данных** — тот же, что использует команда `/usage` в Kimi Code (функции `fetchManagedUsage` / `parseManagedUsagePayload` в `~/.kimi-code/bin/kimi.exe`):

- `GET https://api.kimi.com/coding/v1/usages`
- Заголовки: `Authorization: Bearer <access_token>`, `Accept: application/json`
- Токен: поле `access_token` из `~/.kimi-code/credentials/kimi-code.json`. Также есть `expires_at` (unix-секунды); токен живёт 15 минут, его продлевает только запущенный Kimi Code.
- Запрос из node проходит, Cloudflare не мешает (проверено 2026-11-01, ответ 200).

**Живой ответ (2026-11-01):**

```json
{
  "limits": [{"window": {"duration": 300, "timeUnit": "TIME_UNIT_MINUTE"},
              "detail": {"limit": "100", "used": "5", "remaining": "95", "resetTime": "2026-11-01T17:44:53.684695Z"}}],
  "usages": {
    "limit_5h":          {"used_ratio": 0.0524, "reset_time": "2026-11-01T17:44:52Z"},
    "limit_month_total": {"used_ratio": 0.0065, "reset_time": "2026-12-02T00:00:00Z"},
    "limit_month_code":  {"used_ratio": 0.0065, "reset_time": "2026-12-02T00:00:00Z"}
  }
}
```

**Разбор** — чистая функция в `src/limits.ts`, по образцу самого Kimi:

- `usages.limit_5h` → сессия; `usages.limit_7d` → неделя; `usages.limit_month_total` → месяц. `limit_month_code` не показываем.
- `used_ratio` — доля 0..1 (число или строка) → проценты, округление до целого. Нет `used_ratio` — окна нет.
- `reset_time` — ISO-строка, необязательна.
- Окна, которых нет в ответе, не показываются (у текущего тарифа нет `limit_7d`).
- Пустой, битый или не-JSON ответ → `null`.

**Поведение:**

- Только чтение: в файлы Kimi ничего не пишем, токен не продлеваем.
- Опрос вместе с общим обновлением раз в 5 минут.
- Ошибка или протухший токен (401) → остаются последние полученные цифры, в подсказке пометка «устарело — откройте Kimi Code» с причиной. Если `reset_time` окна уже прошёл, это окно показывается как 0%.
- Подсказка при наведении: имя сервиса, время сброса каждого окна, пометка об устаревании.
- Логотип в Status Bar: `resources/kimi.svg` добавляется в `service-icons.woff` через `tools/build-icons.py`, значок `claude-limits-kimi` (`\E003`). SVG берётся с официального сайта Kimi.
- Настройка `claudeLimits.kimiVisibility`: `auto` / `always` / `hidden`, по умолчанию `auto`.

## 4. Режимы отображения

Четыре независимые настройки, общие для Claude, Codex и Kimi:

| Настройка | Значения | По умолчанию |
|---|---|---|
| `claudeLimits.showProgressBars` (есть с 0.3.4) | `true` / `false` | `true` |
| `claudeLimits.labels` (новая) | `words` / `letters` | `words` |
| `claudeLimits.showServiceNames` (новая) | `true` / `false` | `true` |
| `claudeLimits.shortWindowLabel` (новая) | `session` / `5h` | `session` |

`shortWindowLabel` — как называть пятичасовое окно. Пять часов — это скользящий лимит, в нём может быть несколько сессий, поэтому пользователь выбирает сам. По умолчанию `session`, чтобы у текущих пользователей ничего не поменялось.

| Короткое окно | слова | буквы |
|---|---|---|
| `session` | EN `Session`, RU `Сессия` | EN `S`, RU `С` |
| `5h` | EN `5h`, RU `5ч` | EN `5h`, RU `5ч` |

- Неделя и месяц: слова EN `Week / Month`, RU `Неделя / Месяц`; буквы EN `W / M`, RU `Н / М`.
- Sonnet подписан `S:`, кроме одного сочетания `session` + `letters` + EN — там `Sn:`, чтобы не путать с сессией.
- Окна Codex с нестандартной длиной (`Nh`/`Nm`) и подпись `I` (individual) не меняются.
- `showServiceNames = false` убирает `Claude:` / `Codex:` / `Kimi:` во всех состояниях, включая «updating…» и «no data»; остаётся логотип. В подсказке имя сервиса есть всегда.
- Время до сброса `(~3h)` остаётся во всех режимах.
- Смена любой из настроек сразу перерисовывает индикаторы.

Примеры:

```
[лого] Claude: Session: ███░░░░░ 🟢42% (~3h) | Week: ██░░░░░░ 🟢18% (~4d)   по умолчанию
[лого] 5h: 🟢42% (~3h) | W: 🟢18% (~4d) | S: 🟢5%                           всё компактно, 5h
[лого] S: 🟢42% (~3h) | W: 🟢18% (~4d) | Sn: 🟢5%                           всё компактно, session
[лого] Kimi: S: 🟢5% (~2h) | M: 🟢1% (~30d)                                  Kimi, буквы, без шкал
```

## 5. Правило видимости `auto`

Для Codex и Kimi: **показывать, если есть логин**, то есть существует файл входа — `~/.codex/auth.json` или `~/.kimi-code/credentials/kimi-code.json`. Claude — как сейчас.

- Установленное расширение (`openai.chatgpt`, `moonshot-ai.kimi-code`) без логина индикатор не включает. Это меняет поведение 0.3.4, где `codexDetected` учитывал установленное расширение.
- Логин проверяется при каждом обновлении, а не кешируется. После выхода из аккаунта индикатор скрывается, кешированные имя аккаунта и лимиты сбрасываются.
- `always` / `hidden` работают как раньше.

| Ситуация | Codex | Kimi |
|---|---|---|
| Не входил | скрыт | скрыт |
| Вошёл, приложение закрыто | свежие цифры (app-server запускаем сами) | последние цифры, пометка «устарело» |
| Вошёл, приложение открыто | свежие цифры | свежие цифры |
| Вышел | скрыт | скрыт |

## Критерии готовности

1. Все тесты зелёные, включая новые:
   - разбор ответа Kimi: живой пример выше, ответ с `limit_7d`, пустой, битый, `used_ratio` строкой;
   - прошедший `reset_time` → 0%;
   - форматирование во всех 16 сочетаниях настроек вида (EN и RU), `Sn` для Sonnet только в `session` + `letters` + EN;
   - `auto`: показ при наличии файла входа, скрытие без него, установленное расширение без логина не показывает.
2. В установленном VSIX индикатор Kimi показывает тот же процент сессии, что `/usage` в Kimi Code.
3. Без файла входа Kimi в режиме `auto` индикатора Kimi нет.
4. Переключение каждой из четырёх настроек вида сразу меняет все индикаторы.
